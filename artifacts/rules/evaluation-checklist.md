# 평가 체크리스트 — 무브펫

광고 제안·견적의 고객 조건과 제출 품질을 12개 항목으로 검사합니다. 포커싱온이 무브펫에 제출할 제안서·견적서를 고객 제출 기준으로 평가하는 평가자용 기준입니다.

## 기준 식별

- 기준 버전: movepet-checklist-v1, 2026-10-11 확정. 요구사항 정의서 movepet-requirements-v1을 기준으로 합니다.
- 원문 행 번호는 2026-10-11에 읽은 파일 기준입니다. 링크는 해당 파일의 절로 이동하며 행 번호·표 항목을 함께 적었습니다.
- 사용 입력·양식·요구사항:

| 문서 역할 | 실제 경로 | 적용 범위 |
| --- | --- | --- |
| 클라이언트 브리프 | [sources/brief.md](../../sources/brief.md) | 고객·제품·목표·매체·계약·성과 가정·일정·보고·제출 내용 |
| 회사 소개서 | [docs/about-company.md](../../docs/about-company.md) | 제안사 식별, 핵심 가치, 표현 지양점, 계약·계정 확인 범위 |
| 업무 사규 | [docs/company-rules.md](../../docs/company-rules.md) | 수수료·VAT·배분·업무 범위·확인 절차·상황별 적용 |
| 프로젝트 작업 지침 | [docs/project-instructions.md](../../docs/project-instructions.md) | 입력 해석·작성·검토 원칙 |
| 제안·견적 양식 | [references/templates/proposal-quote-template.md](../../references/templates/proposal-quote-template.md) | 표제, 1~9절의 필수 구성·표 열·행, 참고자료 |
| 요구사항 정의서 | [artifacts/rules/requirements.md](requirements.md) | R001~R099의 요구·원문 위치·검사 ID 연결안 |

- 사용 범위: 이 체크리스트는 평가자 전용입니다. 작성자에게 전달하지 않습니다. 반려 시에는 해당 라운드의 `revision-request.md`로 N 항목의 위치·사유·수정 요청만 전달합니다.
- 독립 검산 전제: 평가 시 [검산 스크립트](../scripts/verify_quote_performance.py)로 현재 초안의 입력값을 재계산합니다. 입력 형식·실행 방법은 [artifacts/scripts/README.md](../scripts/README.md)와 [AGENTS.md / 검산 스크립트](../../AGENTS.md#검산-스크립트)를 따릅니다. 스크립트를 실행하지 못한 평가는 판정 규칙 5에 따라 미완료로 기록합니다.

### C01 목표와 예상 성과

- 1절 표에 지표·목표·월별 및 누적 예상·목표와의 차이·개선 방안 열이 있다.

- N 예: 목표 변경·완화, 예상치를 목표나 실적처럼 표시, 월 또는 누적 행 누락, 차이 값 오기·방향 오류, 미달 구간 대응 누락, 신규 고객 예상치 작성, 6절과 다른 값 기재.

### C04 성과 계산과 근거

- 입력 근거: 1개월차 네이버 500원·3%, 메타 400원·1%; 2개월차 네이버 500원·3.5%, 메타 350원·1.5%; 3개월차 네이버 500원·4%, 메타 300원·2%를 원문 위치와 함께 적는다. 이 값은 매체 합산 계획값이며 실측치가 아니다.

- N 예: 입력값 오기, 전제 누락, 산식·성과 행 누락, 재계산 불일치, 단순 평균 사용, 표시 단위 미기재, 실측 갱신·추적 누락 확인·0 분모 처리 누락.

- N 예: 포함·제외 업무 누락, 수량·주기 누락, 범위 변경, 승인 없는 추가 비용.

### C12 정산과 승인 범위

- 정산: 월 선집행 후 정산, 익월 초 인보이스 발행을 적는다.
- 문서 성격: 계약 전 제안·견적이며 계약 체결·집행 승인이 아님을 적는다. 예상 성과·검토 결과를 실제 성과나 승인으로 표현하지 않는다.
- 실제 계약 여부·광고 계정 접근·과세 및 청구 조건은 계약·집행 전 별도 확인 사항으로 둔다.
- 표제에 고객사·제품, 제안사 포커싱온, 기준 자료의 링크·버전을 적고 제안사와 고객사를 혼동하지 않는다. 참고자료에 브리프·적용 회사 문서·요구사항 경로를 적는다.
- 고객 제출 본문은 양식 구성이며, 수정 전후 내역·평가 상태·판정과 노트온 샘플의 내용·수치를 넣지 않는다.
- N 예: 정산·인보이스 시점 누락, 계약 전 제안 명시 누락, 승인·체결 표현, 표제·참고자료 누락, 본문 내 검토 기록·샘플 내용.

## 검산 기준값

브리프 조건에서 파생한 값이며 브리프에 직접 제공된 금액은 아닙니다. 평가 시 검산 스크립트의 재계산 결과와 대조합니다.

| 구분 | 월별 값 | 3개월 합계 | 산식 |
| --- | --- | --- | --- |
| 순매체비 | 2,371,542원 | 7,114,626원 | M+round(M×0.15)+round((M+round(M×0.15))×0.10)=3,000,000을 만족하는 정수 M |
| 수수료 | 355,731원 | 1,067,193원 | round(M×0.15), 원 단위 반올림 |
| 공급가액 | 2,727,273원 | 8,181,819원 | M+수수료 |
| VAT | 272,727원 | 818,181원 | round(공급가액×0.10), 원 단위 반올림 |
| 청구 총액 | 3,000,000원 | 9,000,000원 | 공급가액+VAT, 계약 총액은 월 청구액 합 |

- 성과 기준값은 작성자가 정한 매체 배분에 따라 달라지므로 고정값을 두지 않습니다. 초안의 4절 배분 금액과 브리프 입력으로 매 평가마다 재계산합니다.

## 기준 확정·판정 규칙

1. 원문의 요구를 위 12개 항목에 연결한다. 표현·양식·계산의 같은 문제를 별도 항목으로 중복 집계하지 않는다. 각 요구는 위 연결 표의 주 검사 항목에서 판정한다.
2. 한 가지 잘못된 값·문장이 여러 절로 옮겨지거나 전파된 경우, 그 원문 요구를 맡은 항목에만 N을 준다. 다른 항목은 ‘참조 Cxx’로 기록하고 그 원인만으로 N을 주지 않는다. 예: 순매체비 오류는 C05에 N, C03·C04·C06은 참조. 6절의 잘못된 값을 1절이 그대로 옮긴 경우 C04에 N, C01은 참조.
3. 서로 다른 필수 내용이 각각 빠진 경우는 독립된 누락이다. 양식의 한 절이 통째로 없으면, 그 절에 들어갈 각 검사 주제의 필수 내용이 문서 어디에도 없는지 항목별로 확인하고, 없으면 해당 항목마다 자기 누락만 사유로 N을 준다. 예: 9절이 없고 다른 위치에도 견적표·계약 합계·업무 범위·정산이 없으면 C05·C06·C11·C12가 각각 자기 내용의 누락으로 N이다. 같은 내용이 문서의 다른 위치에 정확히 있으면 그 항목은 내용 충족으로 판정한다.
4. 항목의 조건을 모두 충족하면 `Y - 통과`, 실제 누락·오류가 있으면 `N - 반려`다. 모든 판정에 이유·재계산 근거·초안 위치·요구사항 원문 위치를 남기고, 모든 N에는 수정 요청을 함께 남긴다. 통과 수는 실제 Y 개수/전체 항목 수(12)로 기록한다. 전 항목 Y와 독립 검산 완료를 모두 충족해야 통과한다.
5. 독립 검산: C01·C03·C04·C05·C06의 수치는 `artifacts/scripts/`의 검산 스크립트로 현재 초안의 입력값을 재계산해 판정한다. 스크립트가 없거나 실행하지 못했거나 일부 수치를 검산하지 못했으면 종합 판정은 미완료이며 통과로 기록하지 않는다. 실행 경로·명령·입력값·결과를 평가 기록에 남긴다.
6. 일치 기준: 반올림 전 재계산 값을 문서가 밝힌 표시 단위로 반올림한 값이 문서 값과 같으면 일치다. 금액은 원 단위로 정확히 일치해야 한다. 표시 단위를 밝히지 않은 성과 값은 C04의 N 사유다.
7. 목표 미달 자체는 반려 사유가 아니다. 목표와 예상의 구분·산식·차이·대응이 맞는지 검사한다. 사용자 승인 없이 예산·기간·수수료율·업무 범위·판정 조건을 완화하지 않는다. 입력 부족·충돌을 발견하면 원문·계산 영향·필요한 결정을 사용자에게 확인한다.
8. 첫 평가부터 같은 기준을 사용하고 모든 반려 사유를 한 번에 전달한다. 반려 시 같은 라운드의 `evaluation.md`에 판정을 기록하고 N 항목의 위치·근거·수정 요청을 `revision-request.md`로 작성한다.
9. 반려 후 재검사는 제목을 `제안서·견적서 — 반려 사항 수정 후 재검사`로 구분하고 다음 번호 라운드(`r{N+1}`)에 기록한다. 이전 판정을 승계하지 않고 전 항목을 다시 검사하며, 이전 초안 대비 수정 내용과 재검사 결과, 미해결 사항을 ‘이전 검토 대비 변화’에 남긴다.
10. 입력 변경이 승인되면 이전 입력·기준·평가를 보존한다. 이전 판정을 새 조건에 그대로 적용하지 않고 기준 버전을 올려 다시 확정한다.
11. 이 체크리스트와 평가 전체는 작성자에게 전달하지 않는다. 평가자는 초안을 직접 수정하지 않는다.
